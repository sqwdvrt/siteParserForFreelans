# План разработки: этапы и чеклисты

Разбивка на этапы с чёткими границами, зависимостями и критериями завершения. Каждый этап заканчивается проверяемым результатом.

**Назначение:** находит → анализирует → ранжирует → уведомляет. Не биржа, не маркетплейс, не автоотклик, не подача заявок.

**Главный KPI:** ≤ 5 уведомлений в день, большинство релевантны. Оптимизировать релевантность, а не количество источников.

**Архитектура:** См. [ARCHITECTURE.md](./ARCHITECTURE.md) — Clean Architecture, слои domain → usecase → port → adapter.

---

## Политика тестирования и качества

**Правила:**
- После завершения каждого этапа — обязательный проход по коду: поиск уязвимостей и багов
- Тесты должны покрывать **≥ 70%** кода (проверка: `go test -cover`, `pytest --cov`)
- Этап считается завершённым только после прохождения тестов и код-ревью

**Инструменты:**
- **Go:** `go test -cover`, `go vet`, `staticcheck`
- **Python:** `pytest`, `pytest-cov`, `bandit` (security), `ruff` (lint)

## Этап 7: Matching

**Цель:** При появлении нового job_embedding — сравнение с пользователями, отбор кандидатов.

**Механизм:** Embedding similarity (cosine), не keyword filtering. См. [DECISIONS.md](./DECISIONS.md) §6.

### 7.1 Similarity

| # | Задача | Проверка |
|---|--------|----------|
| 1 | SQL: `SELECT user_id, 1 - (embedding <=> $1) as score FROM users WHERE embedding IS NOT NULL` | Возвращает scores |
| 2 | Фильтр по порогу (0.7) | Только score >= threshold |
| 3 | Сортировка по score DESC | Лучшие первыми |

### 7.2 Триггер

| # | Задача | Проверка |
|---|--------|----------|
| 1 | После сохранения job_embedding → запуск matching | В том же пайплайне AI-service |
| 2 | Для каждого user с score >= threshold → кандидат | Список (user_id, job_id, score) |
| 3 | Проверка: нет ли уже в `notifications` | Дедупликация |

### 7.3 Ранжирование (упрощённое)

| # | Задача | Проверка |
|---|--------|----------|
| 1 | Факторы: similarity, budget_level, technologies overlap | Формула match_score |
| 2 | match_score 0–1 | Нормализация |
| 3 | Лимит: топ-N на пользователя или score > X | Не спамить |

**Приоритет:** Релевантность важнее количества. Лучше 2 точных уведомления, чем 5 с шумом.

### 7.4 Тесты (покрытие ≥ 70%)

| # | Задача | Проверка |
|---|--------|----------|
| 1 | Similarity query: тестовые векторы | Корректный порядок |
| 2 | Порог фильтрации | score < 0.7 отсекается |
| 3 | Дедупликация notifications | Повтор не создаётся |
| 4 | Ранжирование: формула match_score | Граничные значения |
| 5 | Пустой users.embedding | Пропуск |

### 7.5 Код-ревью

| # | Проверка | Риск |
|---|----------|------|
| 1 | SQL-инъекция в similarity query | Параметризация |
